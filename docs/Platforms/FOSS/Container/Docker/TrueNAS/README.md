# WeKan on TrueNAS

[TrueNAS](https://www.truenas.com) apps come from the catalog
[truenas/apps](https://github.com/truenas/apps) (LGPL-3.0). New apps go to the
`community` train, under `ix-dev/community/<app>/`. WeKan is not there yet (checked
2026-10-11: no `wekan` path in the whole tree, no app request); Planka and Vikunja are.

## The app

[`ix-dev/community/wekan/`](ix-dev/community/wekan/) is the app folder, modelled on
`donetick`, a single container on SQLite:

| File | What it is |
| --- | --- |
| [`app.yaml`](ix-dev/community/wekan/app.yaml) | Metadata: one category (`productivity`), keywords, sources, `lib_version` 2.3.15 and its hash, catalog `version` 1.0.0 |
| [`ix_values.yaml`](ix-dev/community/wekan/ix_values.yaml) | The image, pinned by tag AND digest (`v12.29@sha256:96658d62...`), and the container names |
| [`questions.yaml`](ix-dev/community/wekan/questions.yaml) | The install form: timezone, Root URL, extra environment variables, run-as user, port, storage, labels, resources |
| [`templates/docker-compose.yaml`](ix-dev/community/wekan/templates/docker-compose.yaml) | The Jinja template on the catalog's `ix_lib` library |
| [`templates/test_values/basic-values.yaml`](ix-dev/community/wekan/templates/test_values/basic-values.yaml) | What CI renders and starts |
| [`README.md`](ix-dev/community/wekan/README.md) | One line, as every app has |

`item.yaml` and `templates/library/base_v2_3_15/` are generated by the catalog's tools
and committed in the PR; they are not kept here.

What the template does, and why:

- One container: WeKan with its bundled FerretDB v1 on SQLite (`WEKAN_DB=ferretdb`), data
  in one dataset mounted at `/data`.
- It runs as the TrueNAS apps user (568 by default, as `run_as`), not the image's `wekan`
  user, and a permissions container makes `/data` theirs first.
- `FERRETDB_STATE_DIR=/data/ferretdb`: FerretDB writes `state.json` to its working
  directory, `/build`, which only the image's own user can write, and it exits when it
  cannot. FerretDB reads every flag from `FERRETDB_*`, so this moves it into `/data`.
- The default port is `30527`: the catalog requires a default that no other app uses,
  and `.github/scripts/port_validation.py` gave 30527 as the next free one on
  2026-10-11. Run it again just before the PR.

## How it was tested

The catalog's own tools all run inside Docker. Without Docker, the template was rendered
with the catalog's library exactly the way its renderer does (Jinja2 with the `do`,
`loopcontrols` and `debug` extensions over `library/2.3.15`, values = test values +
`ix_values.yaml`). It renders to a `permissions` container and a `wekan` container
running as 568:568, with `WEKAN_DB=ferretdb`, `FERRETDB_STATE_DIR=/data/ferretdb`, the
digest-pinned image, the port, the healthcheck and the `/data` bind mount.

Not run here: `ci.py` (renders inside Docker, then `docker compose up --wait`),
`generate_metadata.py`, the `apps_validation` image's `validate`, and an install on
TrueNAS.

## The pull request

From the catalog's `CONTRIBUTIONS.md` and its `app_addition.md` PR template:

1. Open an app request issue first (form `[App Request]: WeKan`, category productivity,
   "official Docker images available").
2. Copy `ix-dev/community/wekan/` from here into a fork. Run the catalog's tools, which
   need Docker: `devbox run copy-lib`, `devbox run app-render community wekan`,
   `devbox run app-test`, `devbox run metadata`, `devbox run ports`. Commit the generated
   `item.yaml` and `templates/library/base_v2_3_15/`, and add `wekan` to
   `cspell.config.yaml`.
3. Open the PR with `?expand=1&template=app_addition.md`, titled
   `Add WeKan to the community train`. Link the issue, the upstream repo, the docs and the
   app version, and link the icon and a screenshot: a maintainer uploads them to
   `media.sys.truenas.net` and gives the URLs for `app.yaml`. The template has a required
   question about whether an AI generated any of the PR; whoever opens the PR answers it.
4. Updates afterwards are automatic: TrueNAS's daily Renovate bumps the image and the
   catalog version. WeKan's tags are `vMAJOR.MINOR`, which is not semver, so
   `.github/renovate-config.js` needs a `customVersioning` entry for
   `ghcr.io/wekan/wekan` - the catalog already has one of that exact shape for nzbget.

# WeKan capnp-es fork

This directory vendors the published build of [capnp-es](https://github.com/unjs/capnp-es)
0.0.16, a pure-JavaScript Cap'n Proto implementation, as `@wekanteam/capnp-es`.
WeKan on Sandstorm uses it to talk to sandstorm-http-bridge over Cap'n Proto RPC
on `/tmp/sandstorm-api` (`imports/sandstorm/bridgeClient.mjs`), replacing the
native node-capnp addon (`capnp.node`), which is built for Node 14 and cannot load
on Node 26.

Upstream: npm `capnp-es@0.0.16`, tag `v0.0.16` at commit
`439f564bffdaf0c2d6376b263c2317b25a0ba00f` (package `gitHead`
`d92d982587bf1ce953b277bc831e5a806247884d`). The npm tarball SHA256 is
`01217c5c26155ec831843feff682a6ab1ce8445796e5f9ffd0b25e88a9053b64` and its npm
integrity `sha512-pqhhnRqGfDdgHa+rz4JVO9j1jnkyqsHRYrD4RBtIwxCknYSRG7Mjs+x3IRfd20u+ZGS0IhW2L7cDv9ZcIkCYhQ==`.
`LICENSE` (MIT) and the upstream README (`UPSTREAM-README.md`) are kept verbatim.
This package has no dependencies and no lifecycle scripts; TypeScript stays an
optional peer dependency, needed only by the schema compiler.

## What the fork changes

Every change is in [`patches/wekan.patch`](patches/wekan.patch), which applied to
the upstream tarball's `dist/` reproduces this directory's `dist/` exactly, and is
marked `WeKan fork:` in the code. The RPC `Conn` was upstream's experimental part
and the bridge exercises all of it:

- **Resolve.** A promise import is redirected to the capability the peer resolves
  it to, or fails with the exception it resolves to. When it resolves to one of
  OUR capabilities after calls already went through the promise, new calls are
  held until a `senderLoopback` Disembargo has gone through the peer and back, as
  the C++ implementation's `PromiseClient::resolve` does; an incoming
  `senderLoopback` is reflected. Upstream ignored Resolve and Disembargo.
- **Release.** The last local reference to an import sends `Release` with every
  reference the peer sent (upstream's `ImportClient.close()` was empty, so nothing
  was ever released); an incoming `Release` frees the export; `Finish` with
  `releaseResultCaps` and `Return` with `releaseParamCaps` release the export ids
  they name (upstream used the loop index and the question id, and never recorded
  the result caps).
- **Tail calls.** A call with `sendResultsTo.yourself` keeps its results and is
  answered with `resultsSentElsewhere`; `Return.takeFromOtherQuestion` collects
  them. A C++ peer answers every call it forwards back this way; upstream left
  those questions pending forever. `canceled` and the third-party forms reject
  instead of hanging, and `noFinishNeeded` suppresses the Finish.
- **Bootstrap.** Serving a bootstrap capability (`initMain`) answered with a null
  pointer and an empty cap table: the cap was added to the message but the root
  was never pointed at it.
- **Unimplemented.** Messages it does not handle are echoed back as the protocol
  requires; an echoed Call or Bootstrap rejects its question. Shutting down
  rejects every pending question.
- **Transport.** `DeferredTransport` queues messages. Upstream kept one Deferred,
  so a message arriving before the reader asked for the next one replaced the
  previous one.
- **Compiler.** A method whose parameter or result type is a struct declared in
  another file (`-> stream`'s StreamResult, Sandstorm's `UiView.ViewInfo`) no
  longer regenerates that struct, which declared the same identifier twice and
  made the module a SyntaxError on load. `dist/capnp/stream.mjs`, which the
  compiler's `/capnp/stream.capnp` import maps to but upstream did not ship, is
  generated from Cap'n Proto 1.2.0's `stream.capnp`.

Known limitation, left as upstream has it: the `$Promise` class generated for a
method result that is another file's struct does not import interfaces that
struct refers to from a third file. In WeKan's schemas that is only
`UiView_ViewInfo$Promise.getGrainIcon()`, a pipelined call on an app-side
interface WeKan never calls.

## How it is verified

`tests/sandstormCapnpRpc.test.cjs` drives each of these messages from a
hand-built peer, and runs the same cases, plus WeKan's bridge calls, against the
reference C++ RPC implementation and Sandstorm's own schemas
(`tests/fixtures/capnp-rpc/mock-bridge.c++`, built by
`releases/sandstorm-capnp-schemas.sh --mock`). The JavaScript WeKan loads is
generated by that script from Sandstorm's schemas into `imports/sandstorm/capnp/`.

Update this fork only from a reviewed, pinned upstream release: unpack it, apply
`patches/wekan.patch`, resolve what no longer applies, and run that test.
